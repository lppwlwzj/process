# Feature Specification: 智能排班助手H5前端应用

**Feature Branch**: `002-schedule-h5-app`  
**Created**: 2026-01-25  
**Status**: Draft  
**Input**: User description: "在这个智能排班助手，做一个前端H5。有两个页面，底部两个tab，一个是智能对话AI页面。一个是日历日程页面。"

## Clarifications

### Session 2026-01-25

- Q: 日程详情页的显示格式和分组方式 → A: 按时间排列，分为早上（00:00-12:00）和下午（12:00-19:00）两个时间段，每行显示时间、医生、护士、客户、项目、备注
- Q: 项目类型和冲突判断规则 → A: 项目类型包括面诊、备牙、戴牙、椅旁、复诊、雕蜡、蜡形试戴；面诊、雕蜡、椅旁不需要做排班冲突判断，可直接插入；备牙、戴牙、复诊、蜡形试戴需要检查医生和诊室冲突
- Q: 护士字段的处理方式 → A: 护士为机动资源，不需要做冲突判断，不需要计算可用护士；如果用户指定了护士，则使用指定护士；如果用户未指定，护士字段为空
- Q: VIP客户优先插入功能 → A: 支持VIP客户优先插入，用户确认指定客户可以优先插入某个诊室某个时间后，后面所有已排好的排班要顺延调整时间
- Q: 备注字段支持 → A: 排班记录包含备注字段，用户可以在创建排班时添加备注，并在日程详情页中查看备注信息

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 智能对话AI页面 (Priority: P1)

用户通过自然语言对话与AI助手交互，查询排班情况、检查时间冲突、创建排班记录。对于不需要冲突判断的项目类型（面诊、雕蜡、椅旁），系统直接插入数据；对于需要冲突判断的项目类型，系统检查冲突后创建；支持VIP客户优先插入并自动顺延受影响排班。

**Why this priority**: 这是核心功能，用户通过对话界面完成所有排班相关操作，是系统的主要交互方式。

**Independent Test**: 可以独立测试对话功能，用户发送消息后能够收到AI响应，完成排班查询和创建任务。

**Acceptance Scenarios**:

1. **Given** 用户打开H5应用，**When** 点击底部"对话"tab，**Then** 显示智能对话AI页面，包含消息列表区域和输入框
2. **Given** 用户在对话页面，**When** 输入"今天王医生13点有空吗"并发送，**Then** 系统通过SSE流式返回AI响应，显示查询结果
3. **Given** 用户在对话页面，**When** 输入"今天下午两点安排李总给客户王小心面诊，备注：客户要求提前准备"，**Then** 系统识别项目类型为面诊（无需冲突判断），直接创建排班记录并显示成功提示
4. **Given** 用户在对话页面，**When** 输入不完整信息（如缺少客户姓名），**Then** 系统询问用户补全缺失信息
5. **Given** 用户在对话页面，**When** 输入"王小心客户优先，今天下午2点给王医生安排备牙"，**Then** 系统识别VIP优先标识，检测到冲突后提示用户确认，用户确认后创建排班并自动顺延受影响排班
6. **Given** AI建议创建排班，**When** 用户点击确认按钮，**Then** 系统创建排班记录并显示成功提示
7. **Given** 用户发送消息，**When** 网络连接中断，**Then** 系统显示错误提示并提供重试选项
8. **Given** 用户在不同设备上登录，**When** 查看对话历史，**Then** 系统显示该用户的完整对话记录

---

### User Story 2 - 日历日程页面 (Priority: P1)

用户通过日历视图查看和管理排班日程，支持按日期、医生、诊室筛选。点击日历上的日期可跳转到该日期的详情页，查看该日期的所有排班记录。

**Why this priority**: 日历视图是排班管理的核心展示方式，用户需要直观地查看日程安排。

**Independent Test**: 可以独立测试日历功能，用户能够查看指定日期的排班列表，支持筛选和查看详情。

**Acceptance Scenarios**:

1. **Given** 用户打开H5应用，**When** 点击底部"日程"tab，**Then** 显示日历日程页面，默认显示今天的排班列表
2. **Given** 用户在日程页面，**When** 点击日历上的某个日期，**Then** 跳转到该日期的详情页，显示该日期的所有排班记录
3. **Given** 用户在日期详情页，**When** 查看排班列表，**Then** 排班记录按时间排列，分为早上（00:00-12:00）和下午（12:00-19:00）两个时间段显示
4. **Given** 用户在日期详情页，**When** 查看排班记录，**Then** 每行显示时间、医生、护士、客户、项目、备注等信息
5. **Given** 用户在日程页面，**When** 选择医生筛选条件，**Then** 仅显示该医生的排班记录
6. **Given** 用户在日期详情页，**When** 点击返回按钮，**Then** 返回到日历日程页面
7. **Given** 用户在日程页面，**When** 滑动查看不同日期，**Then** 日历和排班列表同步更新

---

### User Story 3 - 底部Tab导航 (Priority: P2)

用户通过底部Tab栏在对话页面和日程页面之间切换。

**Why this priority**: Tab导航是应用的基础导航方式，确保用户能够快速切换功能。

**Independent Test**: 可以独立测试导航功能，用户点击不同tab能够正确切换页面并保持状态。

**Acceptance Scenarios**:

1. **Given** 用户在对话页面，**When** 点击底部"日程"tab，**Then** 切换到日程页面，对话页面状态保持
2. **Given** 用户在日程页面，**When** 点击底部"对话"tab，**Then** 切换到对话页面，日程页面状态保持
3. **Given** 用户切换tab，**When** 再次返回原页面，**Then** 页面状态和滚动位置保持不变

---

### Edge Cases

- 当网络连接不稳定时，如何处理SSE连接中断和重连？
- 当用户快速切换tab时，如何避免重复请求和状态冲突？
- 当日历数据量很大时，如何优化加载性能？
- 当用户横屏查看时，界面布局如何适配？
- 当用户未登录时，如何引导用户登录？
- 当排班数据为空时，如何友好地提示用户？
- 当某个时间段没有排班记录时，如何显示空状态？
- 当VIP客户优先插入导致排班时间超出营业时间时，如何处理？
- 当用户输入的项目类型不在支持列表中时，如何提示用户？
- 当用户指定的护士不存在时，如何处理？
- 当备注信息过长时，如何在列表中显示？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供智能对话AI页面，支持用户通过自然语言与AI助手交互
- **FR-002**: 系统必须支持SSE流式响应，实时显示AI回复内容
- **FR-003**: 系统必须保存对话历史，用户可以在不同会话中查看历史记录
- **FR-004**: 系统必须提供日历日程页面，以日历和列表形式展示排班信息
- **FR-005**: 系统必须支持点击日历上的日期跳转到该日期的详情页
- **FR-006**: 系统必须在日期详情页按时间排列排班记录，分为早上（00:00-12:00）和下午（12:00-19:00）两个时间段
- **FR-007**: 系统必须在日期详情页的每行排班记录中显示时间、医生、护士、客户、项目、备注等信息
- **FR-008**: 系统必须支持按日期、医生、诊室筛选排班记录
- **FR-009**: 系统必须提供底部Tab导航，支持在对话和日程页面之间切换
- **FR-010**: 系统必须适配移动端H5，支持不同屏幕尺寸和横竖屏切换
- **FR-011**: 系统必须支持项目类型识别：面诊、备牙、戴牙、椅旁、复诊、雕蜡、蜡形试戴
- **FR-012**: 系统必须对不需要冲突判断的项目类型（面诊、雕蜡、椅旁）直接插入数据，无需检查冲突
- **FR-013**: 系统必须对需要冲突判断的项目类型（备牙、戴牙、复诊、蜡形试戴）检查医生和诊室冲突
- **FR-014**: 系统必须将护士作为机动资源处理，不进行冲突判断，不计算可用护士；如果用户指定了护士则使用指定护士，否则护士字段为空
- **FR-015**: 系统必须支持VIP客户优先插入功能，用户确认后自动顺延受影响排班的时间
- **FR-016**: 系统必须支持备注字段，用户可以在创建排班时添加备注，并在日程详情页查看备注
- **FR-017**: 系统必须支持用户确认AI建议的排班方案并创建排班记录
- **FR-018**: 系统必须在用户信息描述不全时询问用户补全信息
- **FR-019**: 系统必须处理网络错误，提供友好的错误提示和重试机制
- **FR-020**: 系统必须支持会话管理，每个用户拥有独立的对话会话
- **FR-021**: 系统必须在页面切换时保持状态，避免数据丢失

### Key Entities

- **对话消息**: 包含消息内容、发送时间、发送者（用户/AI）、消息类型（文本/确认/错误）
- **排班记录**: 包含日期、开始时间、结束时间、医生、护士、客户、项目类型、诊室、备注等信息
  - 项目类型：面诊、备牙、戴牙、椅旁、复诊、雕蜡、蜡形试戴
  - 护士为机动资源，可选字段，不进行冲突判断
  - 备注字段支持用户添加和查看
- **用户会话**: 包含会话ID、用户ID、创建时间、最后活跃时间、对话消息列表
- **筛选条件**: 包含日期范围、医生ID、诊室名称等筛选参数
- **时间段分组**: 早上时间段（00:00-12:00）和下午时间段（12:00-19:00）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在3秒内完成页面加载并看到初始内容
- **SC-002**: AI响应通过SSE流式显示，首字延迟不超过1秒
- **SC-003**: 用户可以在5秒内完成从对话页面到日程页面的切换
- **SC-004**: 日历页面支持流畅滚动，滚动帧率不低于30fps
- **SC-005**: 90%的用户能够成功完成一次完整的排班查询和创建流程
- **SC-006**: 应用在主流移动浏览器（iOS Safari、Android Chrome）上正常运行
- **SC-007**: 页面在不同屏幕尺寸（320px-768px宽度）下正确显示，无布局错乱
- **SC-008**: 网络错误时，用户能够在2秒内看到错误提示并了解重试方法
