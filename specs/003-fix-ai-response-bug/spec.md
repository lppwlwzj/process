# Feature Specification: 修复AI排班助手消息处理Bug

**Feature Branch**: `003-fix-ai-response-bug`  
**Created**: 2026-01-27  
**Status**: Draft  
**Input**: 修复AI智能排班助手对于非排班问题返回固定响应的Bug

## 问题描述

当用户向AI智能排班助手提问与排班无关的问题时（如"你好"、"现在几点了"），系统总是返回固定响应"我来帮您查询2024-12-20的排班情况。"，而不是根据用户输入正确处理并返回友好的响应。

**根本原因**：用户消息没有正确传递给LLM模型，导致模型收到空消息数组，返回了缓存或默认的固定响应。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 日常问候对话 (Priority: P1)

用户向AI排班助手发送日常问候（如"你好"、"早上好"、"谢谢"），期望获得友好的回复，而不是排班相关的响应。

**Why this priority**: 这是最基本的对话交互，用户体验的第一印象取决于AI能否正确识别非排班意图并友好回复。

**Independent Test**: 可以通过发送"你好"消息独立测试，验证AI返回友好问候而非排班信息。

**Acceptance Scenarios**:

1. **Given** 用户已进入AI排班助手对话界面, **When** 用户发送"你好", **Then** AI应返回友好的问候回复（如"你好！有什么可以帮助您的吗？"）
2. **Given** 用户正在与AI对话, **When** 用户发送"谢谢", **Then** AI应返回礼貌的回应（如"不客气，还有其他需要帮助的吗？"）
3. **Given** 用户已进入对话界面, **When** 用户发送"早上好", **Then** AI应返回对应时间的问候

---

### User Story 2 - 非排班相关咨询 (Priority: P1)

用户向AI询问与排班无关的问题（如"现在几点了"、"今天天气怎么样"、"你是谁"），期望AI能够正确识别并给出合理的回应。

**Why this priority**: 用户可能会自然地询问各种问题，AI需要正确区分排班相关和非排班相关的意图。

**Independent Test**: 可以通过发送"现在几点了"消息独立测试，验证AI正确识别并回应。

**Acceptance Scenarios**:

1. **Given** 用户已进入对话界面, **When** 用户发送"现在几点了", **Then** AI应回复当前时间或说明无法获取时间
2. **Given** 用户已进入对话界面, **When** 用户发送"你是谁", **Then** AI应介绍自己是智能排班助手及其功能
3. **Given** 用户已进入对话界面, **When** 用户发送"你能做什么", **Then** AI应列出其主要功能（查询排班、创建排班等）

---

### User Story 3 - 排班相关查询 (Priority: P1)

用户向AI发送排班相关请求（如"查询明天的排班"、"帮我安排一个面诊"），期望AI正确处理排班操作。

**Why this priority**: 这是AI排班助手的核心功能，必须确保在修复非排班问题的同时不影响正常排班功能。

**Independent Test**: 可以通过发送"查询今天的排班情况"消息独立测试，验证AI正确调用排班工具。

**Acceptance Scenarios**:

1. **Given** 用户已进入对话界面, **When** 用户发送"查询明天的排班", **Then** AI应调用排班查询工具并返回排班信息
2. **Given** 用户已进入对话界面, **When** 用户发送"帮我查询下今天的排班情况", **Then** AI应查询今天日期的排班数据并展示

---

### Edge Cases

- 用户发送空消息时如何处理？
- 用户发送模糊意图的消息时（如"帮帮我"），AI如何判断是否为排班相关？
- 用户消息包含排班关键词但实际非排班意图时（如"我想了解一下你们的排班系统是怎么工作的"）如何处理？
- 会话上下文中存在历史消息时，如何确保正确传递给模型？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须将用户消息正确传递给LLM模型，确保模型接收到完整的消息内容
- **FR-002**: 系统必须在消息为空或传递失败时提供有意义的错误处理，而非返回固定响应
- **FR-003**: 系统必须确保会话历史（chat_history）正确序列化并传递给模型
- **FR-004**: AI必须能够区分排班相关问题和非排班问题，并作出相应的回复
- **FR-005**: 对于非排班问题，AI必须直接友好回复，不调用排班相关工具
- **FR-006**: 对于排班问题，AI必须正确使用排班工具完成操作

### Assumptions

- 系统使用 DeepSeek API 作为 LLM 后端
- 系统基于 LangChain/LangGraph 框架实现 Agent 逻辑
- 现有的 prompt 配置（prompt.js）已正确描述了意图判断规则

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户发送"你好"等问候语时，100%获得友好回复而非固定的排班查询响应
- **SC-002**: 用户发送非排班问题时，AI能在3秒内正确识别意图并回复
- **SC-003**: 用户发送排班相关请求时，AI正确调用排班工具的成功率达到95%以上
- **SC-004**: 系统日志不再出现"received empty messages array"错误
- **SC-005**: 所有用户消息能够完整传递给LLM，消息传递成功率达到100%
