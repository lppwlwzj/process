# 排班管理功能规范

## 功能概述

新增排班管理功能，允许管理员创建、修改和删除排班记录。排班记录包含项目、医生、护士、客户、诊室和时间信息，支持按日期和医生进行筛选，并以嵌套表格的形式展示排班信息。系统会检查医生、护士和诊室的时间冲突，确保同一时间段内不会出现重复排班。

## 用户场景

### 场景 1：创建排班记录
管理员需要为某位医生安排一次诊疗排班：
1. 管理员进入排班管理页面
2. 点击"新增"按钮
3. 选择项目类型
4. 选择医生（从医生列表中选择）
5. 选择护士（从护士列表中选择）
6. 选择客户（从客户列表中选择）
7. 选择诊室（从4个诊室中选择）
8. 选择开始时间（年月日时分）
9. 填写时长（分钟）
10. 系统自动计算并显示结束时间
11. 填写备注（可选）
12. 点击"保存"完成创建

### 场景 2：查看排班列表
管理员需要查看某一天的排班安排：
1. 管理员进入排班管理页面
2. 在日期选择器中选择日期
3. 系统显示该日期下的所有排班记录
4. 每个日期下以子表格形式展示该日期的时间段信息

### 场景 3：按医生筛选
管理员需要查看某位医生的排班情况：
1. 管理员进入排班管理页面
2. 在医生下拉框中选择医生
3. 系统显示该医生的所有排班记录
4. 记录按日期分组，每个日期下显示时间段信息

### 场景 4：修改排班记录
管理员需要修改已创建的排班信息：
1. 管理员在排班列表中点击"编辑"按钮
2. 系统弹出编辑对话框，显示当前排班信息
3. 管理员修改需要变更的字段
4. 点击"保存"完成修改

### 场景 5：删除排班记录
管理员需要删除某个排班记录：
1. 管理员在排班列表中点击"删除"按钮
2. 系统弹出确认对话框
3. 管理员确认删除
4. 系统删除该排班记录

## 功能需求

### FR1：排班记录管理
- **FR1.1**：系统应支持创建排班记录，包含以下必填字段：
  - 项目选择（下拉选择）
  - 医生选择（下拉选择，从 user 表中 role='医生椅旁技师' 的用户获取）
  - 护士选择（下拉选择，从 user 表中 role='其他人员' 的用户获取）
  - 客户选择（下拉选择，从 customer 表获取）
  - 诊室选择（下拉选择，选项：诊室1、诊室2、诊室3、诊室4）
  - 开始时间（日期时间选择器，格式：年月日时分）
  - 时长（数字输入，单位：分钟）
  - 备注（文本输入，可选）
- **FR1.2**：系统应自动计算结束时间（开始时间 + 时长），格式为年月日时分
- **FR1.3**：系统应支持修改已存在的排班记录
- **FR1.4**：系统应支持删除排班记录，删除前需确认

### FR2：数据来源
- **FR2.1**：客户列表应从 `customer` 表获取，显示 `customer_name` 字段
- **FR2.2**：医生列表应从 `user` 表获取，筛选条件为 `role='医生椅旁技师'`，显示 `username` 字段
- **FR2.3**：护士列表应从 `user` 表获取，筛选条件为 `role='其他人员'`，显示 `username` 字段
- **FR2.4**：项目选择应为预定义的下拉选项列表

### FR3：筛选功能
- **FR3.1**：系统应提供日期选择器，允许用户选择日期进行筛选
- **FR3.2**：系统应提供医生下拉选择器，允许用户选择医生进行筛选
- **FR3.3**：筛选条件可以组合使用（同时按日期和医生筛选）
- **FR3.4**：系统应提供"重置"按钮，清除所有筛选条件

### FR4：表格展示
- **FR4.1**：排班列表应以嵌套表格形式展示
- **FR4.2**：外层表格按日期分组，显示日期信息
- **FR4.3**：每个日期下展开子表格，显示该日期下的所有排班时间段
- **FR4.4**：子表格应显示以下列：
  - 开始时间
  - 结束时间
  - 项目
  - 医生
  - 护士
  - 客户
  - 诊室
  - 备注
  - 操作（编辑、删除按钮）
- **FR4.5**：表格应支持展开/折叠功能，默认展开当前日期

### FR5：数据验证
- **FR5.1**：创建/修改排班时，所有必填字段必须填写
- **FR5.2**：开始时间不能早于当前时间（可选，根据业务需求决定）
- **FR5.3**：时长必须大于 0
- **FR5.4**：同一医生在同一时间段不能有重复排班，冲突时禁止保存并提示具体错误信息："该医生在此时间段已有排班，请选择其他时间！"
- **FR5.5**：同一护士在同一时间段不能有重复排班，冲突时禁止保存并提示具体错误信息："该护士在此时间段已有排班，请选择其他时间！"
- **FR5.6**：同一诊室在同一时间段只能被一个排班使用，冲突时禁止保存并提示具体错误信息："该诊室在此时间段已被占用，请选择其他诊室或时间！"
- **FR5.7**：如果同时存在多种冲突（如医生和诊室都冲突），应分别提示所有冲突类型

## 成功标准

1. **功能完整性**：用户能够成功创建、修改和删除排班记录，所有必填字段验证正常
2. **数据准确性**：结束时间计算准确，显示格式正确（年月日时分）
3. **筛选有效性**：日期和医生筛选功能正常工作，筛选结果准确
4. **展示清晰性**：嵌套表格结构清晰，日期分组和子表格展示正确
5. **用户体验**：操作流程顺畅，错误提示明确，响应时间在 2 秒内

## 关键实体

### 排班记录 (Schedule)
- `id`：主键ID
- `project`：项目类型
- `doctor_id`：医生ID（关联 user 表）
- `nurse_id`：护士ID（关联 user 表）
- `customer_id`：客户ID（关联 customer 表）
- `room`：诊室名称（varchar，可选值：诊室1、诊室2、诊室3、诊室4）
- `start_time`：开始时间（datetime）
- `duration`：时长（分钟，int）
- `end_time`：结束时间（datetime，自动计算）
- `remark`：备注（varchar(1000)，可选）
- `created_at`：创建时间
- `updated_at`：更新时间

## 假设

1. 项目类型为预定义的固定选项列表
2. 一个医生在同一时间段只能有一个排班（可选，根据业务需求）
3. 排班记录一旦创建，客户和医生信息不会频繁变更
4. 系统使用 MySQL 数据库存储排班数据
5. 前端使用 Vue 3 + Element Plus 框架
6. 后端 API 遵循现有的 RESTful 风格

## 已确认问题

1. **项目类型选项**：使用固定选项列表，前端配置（选项待定义）
2. **时间冲突检查**：需要检查同一医生在同一时间段是否有重复排班，冲突时禁止保存并提示错误
3. **历史排班**：保留所有历史记录，可通过筛选查看
4. **权限控制**：所有登录用户都可以管理排班

- Q: 备注字段的约束规则？ → A: 可选字段，最大长度 1000 字符
- Q: 当发生时间冲突时，错误提示的详细程度？ → A: 分别提示具体冲突类型（如"该医生在此时间段已有排班"、"该护士在此时间段已有排班"、"该诊室在此时间段已被占用"）

## 依赖关系

- 依赖 `customer` 表提供客户列表
- 依赖 `user` 表提供医生和护士列表
- 需要创建新的 `schedule` 表存储排班数据
- 需要后端 API 支持排班的 CRUD 操作
- 需要前端路由配置，添加排班管理页面路由

## 技术约束

- 前端：Vue 3 + TypeScript + Element Plus
- 后端：Node.js/Express 或 Python/FastAPI（根据项目当前使用的后端）
- 数据库：MySQL
- 时间格式：开始时间和结束时间使用 datetime 类型，前端显示格式为"YYYY-MM-DD HH:mm"
